# v6 — Demo Shop + Intentional Bug

## Goal

A real target application with a real bug, so capture → replay → compare
has something worth catching.

## What is real

`examples/demo_shop/` — FastAPI + SQLAlchemy (SQLite locally, Postgres
under Compose): users, inventory, orders, order items, payments, and a
checkout that runs seven statements in one transaction.

**The bug — concurrent inventory reservation** (spec §21):

    Reserve.READ_THEN_WRITE (default)
        available is read, decided on in Python, then written back as an
        absolute value. Two checkouts that interleave between the read and
        the write both believe the last unit is theirs.

    Reserve.ATOMIC (DEMO_SHOP_LOCK_INVENTORY=1)
        UPDATE inventory SET available = available - :qty
         WHERE sku = :sku AND available >= :qty
        The loser's UPDATE matches no row; that checkout is rejected 409.

## DoD — the full demo

```bash
# one unit in stock, two shoppers at once, recorded
curl -X POST 'localhost:3000/api/v1/reset?stock=1'
infractl capture start --listen :8082 --upstream :3000 --title "oversell race"
curl ... /api/v1/checkout &  curl ... /api/v1/checkout &  wait
infractl capture stop <id>

curl localhost:3000/api/v1/orders
{"confirmed_orders": 2, "stock_left": 1}        # one unit sold twice

# reproduce it from the recording
curl -X POST 'localhost:3000/api/v1/reset?stock=1'
infractl replay <id> --target http://127.0.0.1:3000 --concurrency 2
summary: {'MATCH': 16, 'DIFFERENT': 0, ...}      # the bug is still there

# fix it, replay the same recording again
DEMO_SHOP_LOCK_INVENTORY=1 uvicorn examples.demo_shop.app:app --port 3000
curl -X POST 'localhost:3000/api/v1/reset?stock=1'
infractl replay <id> --target http://127.0.0.1:3000 --concurrency 2
summary: {'MATCH': 12, 'DIFFERENT': 2, 'MISSING': 2, ...}

DIFFERENT  postgres.result  rows_affected 1 -> 0
DIFFERENT  http.response    status 201 -> 409  body {... 'error': 'out_of_stock'}
```

The comparison names the fix exactly: the reserving `UPDATE` now matches no
row, and the second shopper is turned away instead of oversold.

Verified by `tests/integration/test_live_replay.py::test_oversell_is_reproduced_then_fixed`.

## Note on replaying a race

A concurrency bug only reproduces under concurrency — replayed one request
at a time, the second checkout simply finds the shelf empty. `--concurrency`
is what makes the recorded race reproducible, and it is the honest way to
present this: the recording holds what happened, the replay decides how
hard to push.
