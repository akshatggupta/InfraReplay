# v11 — External Service Mocking

## Goal

A replay re-runs a customer's checkout. Without v11 it would also re-run the
customer's card charge. Replay must never reach real external services by
default — payments, email, SMS, shipping — and that must be the default with no
flag needed.

## What is real

- **A real external service.** `examples/payment_gateway/` is its own service
  (`:4000`) with an API key and a ledger of every charge it has accepted. The demo
  shop no longer decides payments in-process: every checkout makes a real
  outbound HTTP call to `POST /v1/charges`, authenticated with
  `Authorization: Bearer …`, exactly as a shop calls Stripe.

- **Outbound capture** (`infrareplay/agent/egress.py`). The application builds
  its HTTP client on `agent.http_transport()` — one line. During a capture, each
  outbound call and its answer are recorded as `http.request` / `http.response`
  events with `direction: "outbound"`, in the same correlation group as the
  inbound request that caused them. The gateway API key is masked like any other
  `Authorization` header.

- **Recorded answers on replay.** The replay engine tells the target which
  original request each replayed request reproduces
  (`x-infrareplay-replay-of`, `x-infrareplay-source-correlation`). When the
  shop calls out during a replay, the transport looks up the recorded answer for
  that call (`GET /api/recordings/{id}/externals`) and returns it — the real
  gateway is never contacted. The Nth identical call gets the Nth recorded
  answer.

- **Fails closed.** A call the original never made gets a `503` with
  `external_call_not_recorded`, not a real request. Live calls during a replay
  need an explicit `--externals live`.

- **Only inbound requests are replayed.** The engine skips `outbound` events;
  the target makes its own outbound calls, which are answered from the
  recording.

## DoD

Replaying a recording that originally called the payment gateway hits the
recording instead, with no flag — and the gateway's own ledger proves it: the
charge count after the replay is the same as before it. With
`--externals live`, the count goes up by one.

Verified by `tests/unit/test_egress.py` (transport contract: pass-through,
record, serve from recording, fail closed, live opt-in) and
`tests/integration/test_externals.py` (the ledger, end to end, on live
services).

## Known limits

- Only HTTP made through the instrumented client is covered. A library that
  opens its own sockets, or SMTP, needs its own capture plugin.
- Matching is by method, host and path, in order. Two calls to the same
  endpoint with different bodies are answered in the order they were recorded.
- **Live externals send what was stored — masked values included.** A card
  token is masked at capture, so with `--externals live` the gateway receives
  `***REDACTED***`: in the demo the originally declined card is then
  *approved*, and the comparison reports it (402 became 200). This is the
  reason recorded is the default. `--sub '***REDACTED***=tok_visa_test'` can
  supply a test value, but it replaces every masked value with the same one —
  per-field substitution is not built.
