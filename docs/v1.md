# v1 — Full Pipeline Demo (synthetic data)

## Goal

Prove the concept end to end. Every layer the real product needs — schema,
plugin registry, storage, replay, comparison, API, CLI, dashboard — is
real and exercised. Only the *data source* is fake.

## What is real

- **Event schema** (`infrareplay/schema/`) with `schema_version` and a
  migration registry.
- **Plugin registry** (`infrareplay/plugins/registry.py`) — loads the
  `infrareplay.plugins` entry-point group, validates each against its
  ABC, exposes plugins by name only. The five built-ins are registered
  the same way a third-party package would be; no core code imports a
  concrete plugin.
- **`storage_fs`** — filesystem blob storage; recording snapshots are
  written here, never inlined in the metadata DB.
- **`redaction_default`** — masks `Authorization`, cookies, tokens, card
  data by default on every captured event.
- **Metadata store** — async SQLAlchemy; SQLite locally, Postgres under
  Docker. `init_db()` bootstraps a fresh DB; Alembic (`migrations/`)
  owns schema changes.
- **Replay engine** — safety check refuses production-looking targets
  without an unsafe override; literal-mapping substitution engine.
- **Comparison engine** — pair-walks linked events, one `ComparatorPlugin`
  per protocol, emits `MATCH / DIFFERENT / MISSING / NEW / ERROR`.
- **API / CLI / dashboard** — one source of truth (the API); CLI and
  dashboard are thin clients.

## What is mocked

- **Capture.** `MockCapturePlugin` generates two fixture recordings of a
  `demo_shop` checkout (`POST /api/v1/checkout` → auth `SELECT` → `BEGIN`
  → `INSERT orders` → `INSERT order_items` → `UPDATE inventory` →
  `INSERT payments` → `COMMIT`):

  | scenario | payment gateway | outcome |
  |---|---|---|
  | clean | card authorized | `COMMIT` → HTTP 201 |
  | buggy | card declined (`insufficient_funds`) | `ROLLBACK` → HTTP 402 |

- **Replay target `mock`.** A deterministic function that always returns
  the canonical *clean* outcome. Replaying the buggy recording against it
  therefore yields real `MATCH` rows (auth, order, line items, inventory)
  and real `DIFFERENT` rows (payment result, final response).

## Definition of Done

`docker compose up` → `infractl demo seed` → open the dashboard → click
into a recording → see the full timeline → hit Replay → see a comparison
with at least one `DIFFERENT` and one `MATCH`. All from seed data, zero
real capture code.

Verified by `tests/integration/test_api_flow.py`.

## Not in v1

Real HTTP capture (v2), real Postgres capture + correlation (v3), real
replay against live targets (v4), comparison hardening against jitter
(v5), the demo shop (v6). Nothing above the capture layer changes when
those land.
