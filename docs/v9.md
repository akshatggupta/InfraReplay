# v9 — Observability

## Goal

Know what InfraReplay is doing without reading its database: how much it
captures, how replays are going, what the comparisons say, and who was
refused — as metrics a dashboard can chart and logs a shipper can index.

## What is real

- **Prometheus metrics** at `GET /metrics` (public, like `/health`, so a
  scraper needs no API key). `infrareplay/observability/metrics.py`:

  | Metric | Type | Labels |
  |---|---|---|
  | `infrareplay_recordings_total` | counter | `kind`, `status` |
  | `infrareplay_events_captured_total` | counter | `event_type` |
  | `infrareplay_capture_errors_total` | counter | — |
  | `infrareplay_active_captures` | gauge | — |
  | `infrareplay_replay_total` | counter | `target_kind` (mock · http) |
  | `infrareplay_replay_failures_total` | counter | `reason` (refused · not_found · error) |
  | `infrareplay_replay_duration_seconds` | histogram | `target_kind` |
  | `infrareplay_comparison_results_total` | counter | `category` |
  | `infrareplay_storage_bytes_total` | counter | — |
  | `infrareplay_auth_denied_total` | counter | — |
  | `infrareplay_http_request_duration_seconds` | histogram | `method`, `route`, `status` |

  Labels are bounded on purpose: a replay target becomes `mock` or `http`,
  never its URL, and HTTP latency is labelled with the **route template**
  (`/api/recordings/{recording_id}`), never the raw path. Every known label
  combination is created at zero on startup, so a series reads 0 instead of
  *no data* before its first increment.

- **Structured JSON logs** via structlog, one object per line. Every API
  request gets a `request_id` — taken from `x-request-id` or generated, and
  echoed back in the response — that rides on every line the request
  produces. Logged: `api.started`, `api.auth_open`, `http.request` (method,
  route, status, ms, actor), `auth.denied`, `capture.started`,
  `capture.stopped`, `replay.finished`, `replay.refused`, `recording.failed`.
  Headers and payloads are never logged — ids, counts and timings only.
  `INFRAREPLAY_LOG_FORMAT=console` for humans, `INFRAREPLAY_LOG_LEVEL`
  to filter. In Docker, uvicorn's access log is off: the JSON
  `http.request` line replaces it.

- **Grafana dashboard** — `docs/grafana/infrareplay-dashboard.json`, 14
  panels: overview stats, capture rate by event type, snapshot bytes,
  comparison results by category, replay p50/p95, failures by reason, API
  latency by route, requests by status. It uses a `datasource` template
  variable, so it imports through the Grafana UI *and* loads through
  provisioning without edits.

- **Prometheus + Grafana in one command**:

      docker compose --profile observability up --build

  Prometheus on `:9090` scraping `api:8000/metrics` every 5s; Grafana on
  `:3001` (3000 is the demo shop) with the datasource and dashboard
  provisioned and anonymous read-only access, so it opens straight onto the
  dashboard.

## DoD

`tests/integration/test_observability.py`:

1. **`/metrics` is scrapeable** — 200, Prometheus text format, parsed with
   `prometheus_client`'s own parser, carrying every metric the spec names.
2. **Counters follow the work** — seeding, a mock replay and a refused
   replay move the right series by the right amounts (deltas, since the
   registry is process-wide).
3. **`/metrics` stays public** with API keys on, while `/api` returns 401.
4. **The dashboard matches the API** — every metric any panel queries is
   one `/metrics` actually exports. Mutation-checked: renaming a queried
   metric fails the test, so the dashboard cannot silently drift.
5. **Logs are JSON and carry no secrets** — every line parses, the request
   id round-trips, and a bearer token sent in a header appears nowhere in
   the log.

## Known limits

- Metrics are per process. With several API replicas, sum across them in
  PromQL (the dashboard already aggregates with `sum by`).
- `infrareplay_storage_bytes_total` counts snapshot bytes handed to storage,
  before encryption — the size on disk is slightly larger when
  `storage_encrypted` is on.
- The demo shop and the dashboard are not instrumented; only the API is.
