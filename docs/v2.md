# v2 — Real HTTP Capture

## Goal

Replace the mock data source with real traffic, without changing anything
above the capture layer.

## What is real

- **`http_capture`** (`infrareplay/plugins/http_capture/`) — a Starlette
  reverse proxy served by uvicorn inside the API process. It records the
  request, forwards it upstream, records the response, and returns the
  upstream's answer to the client unchanged.
- **Correlation headers.** Every forwarded request carries
  `x-infrareplay-correlation-id` and `x-infrareplay-recording-id`. v3 uses
  them; an uninstrumented app simply ignores them.
- **Capture sessions** (`infrareplay/capture/session.py`) — a plugin running
  in the background of the API process, draining into an open recording:

      POST /api/captures              start the plugin, open the recording
      POST /api/captures/{id}/stop    stop the plugin, finalise the recording
      POST /api/captures/{id}/events  ingest events from another process (v3)

- **Body limits.** A body over `INFRAREPLAY_MAX_BODY_BYTES` (64 KiB default)
  is stored as a truncation note, not the payload.
- **Redaction on real traffic.** The same `redaction_default` plugin that
  masked fixture headers masks captured ones — `Authorization` never
  reaches storage.

The mock plugin is untouched and still used by `infractl demo seed`, the
unit tests and CI.

## DoD

```bash
infractl capture start --listen :8081 --upstream :3000
curl -X POST localhost:8081/api/v1/checkout -H 'x-demo-user: dana' \
     -H 'authorization: Bearer secret' -d '{...}'
infractl capture stop <recording-id>
```

The recording appears in the same dashboard and timeline built in v1, with
`authorization` shown as `***REDACTED***`.

Verified by `tests/integration/test_live_capture.py`.

## Not in v2

The proxy captures HTTP only. The SQL those requests trigger arrives in v3.
