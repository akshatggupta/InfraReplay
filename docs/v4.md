# v4 — Real Replay Engine

## Goal

Send a captured recording at a live service and record what really comes
back.

## What is real

- **Live targets** (`infrareplay/replay/http_target.py`) — every captured
  `http.request` is re-sent with httpx; the real status, headers and body
  become the replay's events. A transport failure is recorded as an
  `error` payload, which the comparator reports as `ERROR` rather than
  crashing the run.
- **Replay recordings are opened first.** The replay's recording row exists
  before the first request goes out, so an instrumented target streams its
  SQL into the replay run while it is still in flight. A replay is
  therefore a first-class recording: HTTP *and* database events.
- **Substitution** (`infrareplay/replay/substitution.py`):
  - explicit mapping, `--sub old=new`;
  - templates in the replacement — `${uuid}`, `${now_iso}`, `${now_ns}`;
  - auto mode (`--auto-subs`) gives every UUID-shaped value a fresh id,
    the same replacement wherever that value reappears.
- **Concurrency** — `--concurrency N` sends N requests at once, the only
  way to reproduce a race (see v6).
- **Safety first, literally.** The production-host check runs *before* the
  replay recording is opened, so a refused replay leaves nothing behind.

## DoD

```bash
infractl replay rec_71bd --target http://127.0.0.1:3000
replay rpl_4423 against http://127.0.0.1:3000
summary: {'MATCH': 8, 'DIFFERENT': 0, ...}
```
