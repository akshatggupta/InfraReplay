# v5 — Comparison Engine Hardening

## Goal

Make the comparison survive the real world: a replay against an unchanged
service must report no differences, even though almost every identifier in
it is new.

## What is real

- **Normalisation** (`infrareplay/comparison/normalize.py`), applied by both
  comparators before they diff:

      "ord_9f2c1a7b3e00"                      -> "<id>"
      "3fa85f64-5717-4562-b3fc-2c963f66afa6"  -> "<uuid>"
      "2026-09-21T10:00:00.412Z"              -> "<timestamp>"

  and volatile headers (`date`, `server`, `etag`, `x-request-id`, the
  capture headers, …) are dropped.
- **Configurable ignores** — `INFRAREPLAY_IGNORE_FIELDS=reference,eta_days`
  removes named keys on top of the built-in rules.
- **Everything else is compared exactly.** A 201 that became a 409, a row
  count that changed, a payment that flipped to `declined` — all still
  differences. The tests state this both ways.

## DoD

Replaying the same real recording twice against an unchanged target yields
`MATCH` both times, with no false `DIFFERENT`s from fresh order ids,
payment references or clocks.

Verified by `tests/integration/test_live_replay.py::test_replaying_twice_is_stable`
and `tests/unit/test_normalize.py`.
