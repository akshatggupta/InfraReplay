The loop

every stage runs on real traffic
01

Capture

A reverse proxy records each request; the app's agent records the SQL it ran and the calls it made to other services.

02

Correlate

One correlation id ties every query and outbound call to the request that caused it.

03

Store

Secrets masked before anything is written; snapshots optionally encrypted at rest; every action audited.

04

Replay

The requests are re-sent to a live service; its calls to payments are answered from the recording.

05

Compare

Each pair diffed after fresh ids and clocks are normalised, down to the field that changed.

What capture costs — measured

v10 · Locust, 30 s per run, direct vs captured

The first benchmark run showed capture was unusable under load, and that it lost data. An HTTP client was built for every request — 183 ms each — and SQLite locks were dropping events. The fixes, measured on the same setup:

Running the demo

one container, real traffic on boot

Start API, demo shop, payment gateway and dashboard in one container. It records real checkout traffic as it boots.

docker build -t infrareplay . docker run --rm --name infrareplay -p 8000:8000 -p 8080:8080 -p 3000:3000 -p 4000:4000 -p 8081:8081 infrareplay

Open the dashboard at localhost:8080, or the terminal UI — either works for the whole demo.

docker exec -it infrareplay infractl tui

Record more real traffic: t in the TUI, the button in the dashboard, or the CLI.

docker exec -it infrareplay infractl demo traffic

Replay it against the live shop, and show the gateway's ledger did not move.

docker exec -it infrareplay infractl replay <id> curl localhost:4000/v1/charges

The bug: replay the race, switch the fix on, replay again, compare.

examples/demo_shop/control.sh restock 1 docker exec -it infrareplay infractl replay <race-id> --concurrency 2 examples/demo_shop/control.sh fix on && examples/demo_shop/control.sh restock 1 docker exec -it infrareplay infractl replay <race-id> --concurrency 2

Show the measured cost of capture: 6 in the TUI, or the CLI.

docker exec -it infrareplay infractl benchmark show

What it does not do yet

stated, not hidden

One API process is the ceiling under load. Proxy, ingest and writes share it; captured throughput tops out around it at medium and heavy load. More workers would lift it — not built.

Only HTTP through the instrumented client is stubbed on replay. SMTP, raw sockets, or a library with its own HTTP stack would need their own capture plugin.

BEGIN and COMMIT are not captured, and query results are recorded as row counts, not rows.

Encryption covers stored snapshots. Event rows in the database rely on masking, not encryption.

Benchmarks run on one machine and SQLite. The direct-versus-captured comparison is like for like; absolute numbers are not dedicated-host numbers.
