Where v1 stands

Real & exercised

  • · Versioned Event schema + migration registry
  • · Entry-point plugin registry — 5 built-ins, no core imports a plugin
  • · Async SQLAlchemy metadata store + Alembic
  • · Filesystem blob storage for recording snapshots
  • · Default redaction — Authorization, cookies, card tokens
  • · Replay engine with production-target safety check
  • · Comparison engine — MATCH / DIFFERENT / MISSING / NEW / ERROR
  • · FastAPI + infractl CLI + NiceGUI dashboard

Mocked at v1 — on purpose

  • · Capture. MockCapturePlugin emits a full transactional checkout — no real network or DB traffic
  • · Replay target mock. Deterministic; always returns the clean outcome
  • · Everything downstream of capture is the code v2/v3 will keep

The README says this in plain terms — v1 is an honest prototype of the concept, not a finished product.

How it's built

Plugins, not forks

Capture sources, storage, redaction and comparators are entry-point plugins. The core talks to interfaces only — the mock capture proves it.

The schema is the API

Every component agrees on one Pydantic Event with a schema_version. New fields are additive; breaking changes get a migration.

Safe by default

Replay refuses production-looking targets without an override. Redaction masks credentials on every captured event.
