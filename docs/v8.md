# v8 — Security Hardening

## Goal

Recordings hold real traffic. Nothing secret should be stored, nothing
should be readable without a key, and every action on a recording should
leave a trace of who did it.

## What is real

- **Encryption at rest** — `storage_encrypted`
  (`infrareplay/plugins/storage_encrypted/`) wraps another storage plugin,
  resolved by name through the registry, with Fernet (AES-128-CBC +
  HMAC-SHA256). Turn it on with:

      INFRAREPLAY_STORAGE_PLUGIN=storage_encrypted
      INFRAREPLAY_ENCRYPTION_KEY=$(infractl security keygen)

  A wrong or altered key fails loudly instead of returning garbage, and a
  plaintext blob is reported as one rather than as a decryption failure.

- **API keys** — `INFRAREPLAY_API_KEYS="ci:s3cret,dana:t0ken"`. Every
  `/api` route then needs `x-api-key`; the label becomes the audit actor.
  Comparison is constant-time. `/health`, `/metrics` and the OpenAPI docs
  stay public. With no keys set the API is open — the dev default — and
  `/health` says `"auth": "open"` so nobody assumes otherwise. Clients send
  `INFRAREPLAY_API_KEY`: the CLI, the dashboard, the in-app agent and the
  Docker seeder all do.

- **Audit log** — `audit_log` table (migration `0003_audit_log`), written at
  the API boundary where the caller is known. Recorded: `capture.start`,
  `capture.stop`, `replay.run`, `recording.export`, `recording.import`,
  `demo.seed` — each with outcome `ok` or `failed` — and every refused call
  as `auth.denied`. Substitution *keys* are logged, never their values,
  since those are often fresh credentials. `GET /api/audit`,
  `infractl audit list`.

- **Redaction by shape** — the default redactor already masked values under
  sensitive *keys*. It now also masks bearer tokens, JWTs and provider keys
  (`sk_live_…`, `tok_test_…`) wherever they appear — including SQL
  parameter lists and free text, which no key name would flag.

## DoD

`tests/integration/test_security.py`, on a live stack with keys on and
encryption on:

1. **Secrets never stored or exposed.** A checkout carrying a bearer JWT, a
   session cookie, a card token, a CVV and a JWT in a free-text note is
   captured through the proxy, then replayed with a substituted fresh
   credential. Not one marker appears in any API response (recording,
   export, replay, comparison, audit), in the blob on disk, in the
   decrypted blob, or in the raw bytes of the metadata database file.
2. **Every capture and replay action is audited**, including the refused
   production replay, with the caller's label as actor.
3. **No key, no access** — 401 with and without a wrong key, both audited
   as `auth.denied`, and the guessed key is not written into the log.

The tests were mutation-checked: switching key redaction off, or writing
blobs unencrypted, makes them fail.

## Known limits

- Encryption covers the **blob snapshots**. Event rows in the metadata
  database are protected by redaction, not encryption — encrypt that
  database at the storage layer (Postgres TDE, an encrypted volume) if the
  threat model needs it.
- Shape matching catches common secret formats, not every one. A secret in
  an unusual format needs its key on `_SENSITIVE_KEYS`.
- Key rotation is manual: blobs written under an old key need that key to
  be read.
